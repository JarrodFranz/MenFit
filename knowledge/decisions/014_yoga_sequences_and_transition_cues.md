# 014 — Yoga sequences with timed, cued pose transitions

- **Status:** Accepted (implemented and verified on emulator-5554, 2026-09-04)
- **Date:** 2026-09-04

## Context

The owner's request (2026-09-04, from the Yoga hub on device): *"create a yoga
'routine' where you can put the exercise and how long to be in that pose, and
when doing it the app will tell you (maybe by a nice relaxing chime) to
transition."* Two things were true before this decision:

1. **The app had no notion of a pose sequence.** `MindfulWorkoutDetails` already
   carried a `poses: List<String>` field, but nothing ever populated it. The
   Yoga "Flow Timer" is a single stopwatch with style / focus-area / RPE chips.
2. **Every cue in the app was haptic + visual.** The HIIT tracker signals
   work/rest boundaries with `AccessibilityHaptics.heavyImpact` and a colour
   swap (`hiit_tracker_screen.dart#_onPhaseChanged`). There is no audio
   playback package and no audio asset in the repo. A 2026-09-01 evaluation
   approved `flutter_tts` + `audio_session` for *spoken* coaching cues (not yet
   adopted); a short chime is a different need — a clip player, not speech.

A third, smaller inconsistency surfaced with the same screenshot: the hub's
"Yoga Style Focus" card hard-codes **three** chips while the tracker offers
**seven** styles, from two unrelated literal lists.

## Decision

### 1. Model: one table, poses as a JSON blob — the strength-routine shape

`yoga_sequences` (schema **v23**): `id` (client UUIDv7), `name`, `description`,
`posesJson`, `transitionSeconds` (default 5, 0–60), `style` (nullable, one of
`MindfulStyles.yogaStyles`), `createdAt`, `updatedAt`, `deletedAt` (soft
delete). `posesJson` is a list of `YogaPose { name, holdSeconds (5–600), side
(none/left/right), cue }`. This mirrors `strength_routines.exercisesJson`
exactly, for the same reasons: a sequence is edited and read as a whole, never
queried by pose; a child table would add joins and a migration surface for no
query we have.

`YogaSequence.totalDuration = Σ hold + transitionSeconds × (poses − 1)` — no
transition after the last pose.

Two **starter sequences** exist as domain constants (`YogaSequenceStarters`),
not as seeded rows: the UI offers "Add a starter" which saves a *copy* under a
fresh id. Nothing appears in the user's list that she did not put there.

### 2. Runner: wall-clock phases, cues on transitions only

`YogaSequenceRunnerController` (Riverpod codegen, `keepAlive: true` like every
tracker so a session survives navigation and shows in the Resume banner) is a
phase machine `{pose(i), transition(i→i+1), complete}` with `phaseEndsAt` as a
`DateTime`. A 1 s `Timer.periodic` only *recomputes remaining from the clock*;
it never counts ticks. Pause stores the remaining duration; resume re-anchors.
Skip/back jump phases. A missed or throttled tick therefore never drifts the
sequence — the same property the HIIT controller relies on. The clock is
injectable for tests.

On completion the runner saves an `Activity(type: yoga)` whose
`MindfulWorkoutDetails.poses` is the pose-name list (finally populating the
field), `style` from the sequence, `movingTime` = actual practised time
(skips shorten it; pauses are excluded), RPE **null** until rated.

### 3. Cues: three channels, each independently switchable, fired once per boundary

Cues are emitted from a `ref.listen` on **phase transitions**, not from the
timer, so a boundary reached by countdown or by "skip" fires exactly once:

| Channel | Mechanism | Off switch |
|---|---|---|
| Sound | a ~1.6 s synthesized singing-bowl chime (`assets/audio/transition_chime.wav`, generated by our own script — licence-free, no third-party asset) played through `AudioCuePlayer` in `core/platform/audio/` via the `AccessibilitySound` funnel | Settings › Sound cues (new, default ON) and the runner's own mute toggle |
| Haptic | `AccessibilityHaptics.heavyImpact` (pose start) / `mediumImpact` (transition start) — the existing intensity convention | existing Haptic feedback setting |
| Visual | pose name swap, countdown ring, "next: …" line, colour shift for the transition phase | always on; it is the accessible baseline |

The audio adapter is a `core/platform` seam with a no-op fallback, so a
platform without a working player degrades to haptic + visual rather than
failing. **Package choice and per-platform matrix:** see § Audio package below
(filled from the package evaluation).

### 4. Screen stays awake while a sequence runs

A practice is 5–60 min with the phone on the mat; the runner requests a
screen-awake lock for its lifetime (released on complete/discard/dispose)
through a `core/platform` seam. Keeping the screen on is also what keeps the
Dart isolate alive, which the phase timer depends on. **Package:** see § Audio
package below.

### 5. Styles: one source of truth

`MindfulStyles` (domain) holds the yoga styles, pilates styles and focus areas.
The tracker chips and the hub's style card both read it; the hub shows all
seven yoga styles, and the strings it passes to `setStyle` are the chip labels
themselves so the tracker pre-selects correctly. The hub's "Primary Focus"
tile no longer invents `Flow` when there is no history — it shows an honest
"—".

## Privacy

Sequences and pose names are activity data (S1 per
`knowledge/engineering/security_and_privacy.md`): never logged, never sent
anywhere, included in Delete-my-data from the first commit. **Export:** the app
has no whole-app export mechanism (only per-activity GPX/TCX and the clipboard
cycle export) - a gap for every table, tracked in `deferred.md`, not solved here. The chime is a bundled asset; no network. No pose carries health copy:
names only, no benefit or therapeutic claims (`knowledge/domain/womens_health.md`
evidence gate applies to any future "poses for your phase" idea — not built).

## Audio package

`audioplayers 6.8.1` for the chime and `wakelock_plus 1.8.0` for screen-awake,
both exact pins, both GO-with-conditions in
`knowledge/flutter/package_decisions.md` (2026-09-04 section, with the rejected
alternatives). The conditions that shaped the design:

- **AGP 9 with built-in Kotlin off** (this repo) was predicted to break both
  packages' newest Android modules. **Measured 2026-09-04: it did not** - debug
  and release (R8) builds passed at head versions with no overrides. The
  fallback pins are documented in the package register, unused. Never flip
  `android.builtInKotlin` (measured to fail 2026-08-27).
- **iOS: respect the silent switch** (`ambient`, no explicit options - `mixWithOthers` is implicit there and asserting it explicitly crashes in debug; no ducking).
  A silenced phone stays silent; the runner shows a "chime is muted" affordance
  so the feature never reads as broken. Decided by the orchestrator under the
  app's restraint posture; the owner can reverse it in one line.
- **Android ducks her music** (`gainTransientMayDuck`) and returns it.
- **Windows N/KN**: the published `audioplayers_windows` crashes at startup
  without the Media Feature Pack. Accepted for the dev-only Windows target;
  re-pin before any Windows distribution (deferred row).
- **Web**: chime needs a user gesture first (the Start tap preloads it); the
  wake lock is HTTPS-only and drops when the tab hides.

Per-platform, sound cue: Android full / iOS full (Mac-unverified) / Web degraded
(no duck, gesture-gated) / Windows degraded (no duck; N/KN caveat). Screen
awake: Android, iOS, Windows full / Web degraded.

## Consequences

- Schema v23; one new table; `MindfulWorkoutDetails.poses` populated for
  sequence practices (the manual tracker still leaves it empty).
- Two new `core/platform` seams (audio cue, screen awake) with stubs, tested
  through fakes; the real adapters are exercised on the emulator and in a
  RELEASE build before the round counts as done (ML Kit taught us that).
- A future Pilates sequence is a `type` column away; not built now.

## Alternatives rejected

- **Normalised `sequence_poses` table** — no query needs it; strength routines
  proved the blob is enough.
- **Spoken cues (`flutter_tts`)** — approved separately for run coaching; a
  chime is quieter, language-neutral and cannot mispronounce a pose.
- **Scheduled local notifications per pose** — over-engineering for a
  foreground practice with the screen kept on; revisit only if background
  practice is ever asked for.
- **Seeding starter rows into the table** — the user's list would show items
  she never created; a one-tap "Add a starter" copy keeps the list hers.
